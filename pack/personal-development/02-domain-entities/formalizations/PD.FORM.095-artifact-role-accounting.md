# Формализация: Учёт артефактов созидателя

## 1. Определение

**Артефакт созидателя** — зафиксированный результат учебной или созидательной деятельности пользователя: файл, рабочий продукт, публикация либо изменение формализованного знания. Коммит подтверждает факт изменения носителя, но сам по себе не доказывает качество, длительность работы, освоение метода или ступень.

Артефакты нужны для трёх задач:

1. **Телеметрия поведения.** Классифицированный артефакт превращается в каноническое событие Activity Hub. Только после этого правила PD.FORM.089 могут учесть его в одной или нескольких характеристиках `bh.*`.
2. **Диагностическое свидетельство.** Диагност может открыть артефакт, чтобы проверить ответ по `cp.*`, уточнить уверенность или разобрать расхождение. Артефакт не записывает значение `cp.*` автоматически.
3. **История развития.** Последовательность событий показывает, в каких ролях и проектах действовал пользователь.

**Жёсткая граница:** количество артефактов ≠ качество развития. Ни число коммитов, ни тип репозитория, ни классификация роли не присваивают ступень.

## 2. Контексты хранения

| Репозиторий пользователя | Что содержит | Возможные роли | Способ наблюдения |
|---|---|---|---|
| `personal-strategy/` | Неудовлетворённости, стратегия, Lifework-пакет, планы | Ученик, Стратег | Изменение документа; завершение РП — отдельное событие |
| `personal-knowledge-index/` | Заметки, черновики, посты | Ученик, Просветитель | Коммит; публикация — отдельное подтверждённое событие |
| `PACK-personal/` | Формализации, методы, различения | Ученик, Исследователь | Изменение Pack-сущности после проверки |
| `personal-guide/` | Персональные руководства и выполненные задания | Ученик | Завершение задания или занятия, а не наличие шаблона |

Репозиторий задаёт контекст, но не определяет роль. Черновик в Индексе знаний — след Ученика; подтверждённая публикация того же текста — отдельный след Просветителя.

## 3. Классификация «артефакт → роль»

| Тип артефакта | Признаки | Возможная роль | Ограничение |
|---|---|---|---|
| Выполненное задание | Есть ответ и критерий завершения | Ученик | Шаблон без ответа не считается выполнением |
| Заметка / черновик | Личный материал без публикации | Ученик | Не является передачей другим |
| Стратегический документ | Решение о горизонте, роли, проектах | Ученик / Стратег | Роль подтверждается содержанием, не путём |
| Публикация | Есть адресат и факт публикации | Просветитель | Всегда требует ручного подтверждения |
| Pack-сущность | Новая или содержательно изменённая формализация | Исследователь | Механическая правка не доказывает исследовательскую роль |
| План / ревью | Планирование либо разбор факта | Ученик | Намерение не равно исполнению |
| Системный разбор | Различения применены к реальной ситуации | Интеллектуал / Исследователь | Проверяется содержание и объект применения |
| Рабочий продукт проекта | Завершённый результат с приёмкой | Профессионал / другая проектная роль | Отделяется от учебного упражнения |

При пересечении признаков классификатор хранит основную роль и дополнительные теги свидетельств. Он не выбирает «более высокую» роль ради повышения ступени.

## 4. Event Model

Физическое размещение таблицы `artifact_events` определяется WP-109/WP-253. Нормативный логический контракт:

```
artifact_events
────────────────────────────────────────────────────────────────────
artifact_id                  UUID, PK
user_id                      UUID
repo                         TEXT
file_path                    TEXT
artifact_type                ENUM
primary_role                 ENUM
evidence_tags                TEXT[]
activity_domain              ENUM
source_event_id              UUID | NULL
current_stage_at_creation    INT 1..5 | NULL
attained_stage_at_creation   INT 1..5 | NULL
stage_evaluation_status      ENUM confirmed | indeterminate
classifier_source            ENUM deterministic | model | manual | confirmed
confidence                   FLOAT [0,1]
created_at                   TIMESTAMPTZ
indexed_at                   TIMESTAMPTZ
```

`current_stage_at_creation` — исторический снимок текущей оценки и может быть `NULL`, если недельное bh-окно, телеметрия или стержневой cp-профиль неполны/просрочены. `attained_stage_at_creation` хранит ранее подтверждённую историческую ступень зрелости и также может быть `NULL` до первой полной оценки. Административное зачисление и учебный нарратив ступени 1 не заполняют ни одно из этих полей искусственным значением 1.

Минимальные ограничения согласованности снимка:

```sql
CHECK (current_stage_at_creation IS NULL OR current_stage_at_creation BETWEEN 1 AND 5)
CHECK (attained_stage_at_creation IS NULL OR attained_stage_at_creation BETWEEN 1 AND 5)
CHECK (
  (stage_evaluation_status = 'confirmed' AND current_stage_at_creation IS NOT NULL)
  OR
  (stage_evaluation_status = 'indeterminate' AND current_stage_at_creation IS NULL)
)
CHECK (
  current_stage_at_creation IS NULL
  OR (attained_stage_at_creation IS NOT NULL
      AND attained_stage_at_creation >= current_stage_at_creation)
)
```

Оба поля только контекстны: событие не может переписать их задним числом, не создаёт подтверждение ступени и не использует нарративную ступень для собственного признания. `attained_stage_at_creation` — ступень зрелости, не степень квалификации.

В таблице нет `w_weight`, `m1_weight` … `m4_weight` и нет полей `cp.*`. Старые веса смешивали учебные направления FORM.094 с текущей схемой RCS и создавали обход Диагноста.

## 5. Классификатор

### 5.1 Три шага

```
ШАГ 1. Детерминированные признаки
  path + тип изменения + метаданные публикации/приёмки
  → artifact_type, candidate_role, evidence_tags

ШАГ 2. Модель для неоднозначного содержания
  вход: путь, минимально необходимый фрагмент, diff-stat
  выход: {type, role, evidence_tags, activity_domain, confidence}

ШАГ 3. Ручная проверка
  если confidence < 0.7,
  либо type ∈ {publication, completed-work-product},
  либо роль влияет на критичное решение
```

Модель классифицирует наблюдение, но не оценивает ступень и не создаёт `bh.*`/`cp.*` значения.

### 5.2 Fail-closed

- Нет подтверждения публикации → `draft`, не `publication`.
- Нет критерия приёмки → `work-product-draft`, не завершённый рабочий продукт.
- Нет явного времени → событие не добавляет часы в `bh.inv`.
- Неизвестен инициатор → событие не подтверждает `bh.agn`.
- Неясно, было ли это содержательной практикой → `confidence` снижается и создаётся очередь проверки.

## 6. Маршрут в текущий RCS

```
артефакт
  → классифицированное событие Activity Hub
  → разрешённые агрегаты bh.* Аттестатора
  → независимый диалог и аудит cp.* Диагноста
  → composition rule PD.FORM.089
```

| Наблюдение | Возможный поведенческий потребитель | Что запрещено выводить напрямую |
|---|---|---|
| Дни подтверждённой практики в домене | `bh.sys`, `bh.stb` | `cp.rhy` |
| Явный `slot_logged` или `lesson_completed` | `bh.inv` по FORM.089 | мастерство метода `cp.skl` |
| Подтверждённое применение метода | `bh.met` | качество или глубину применения |
| Событие рефлексии с предусмотренным весом | `bh.awr` | зрелость `cp.wld`/`cp.int` |
| Явно установленный инициатор | `bh.agn` | `cp.agt` |
| Завершённый РП с `actual_hours` | `bh.scl` | уровень охвата или реальное изменение FORM.093 |

Точный список типов событий и формулы находятся в PD.FORM.089 §12. FORM.095 не вводит параллельные веса и не обещает фиксированное соотношение «авто-сигнал / self-report».

### Артефакты в работе Диагноста

Диагност использует артефакт как проверяемое свидетельство:

- запрашивает объяснение выбора метода;
- проверяет, относится ли результат к реальной задаче;
- сопоставляет рассказ с временной линией;
- фиксирует уверенность и дату оценки.

Расхождение `bh ↔ cp` ведёт к уточнению или статусу `indeterminate`, а не к правилу `max()` и не к автоматическому повышению.

## 7. Учебный ≠ созидательный артефакт

| | Учебный артефакт | Созидательный артефакт |
|---|---|---|
| Назначение | Освоить или проверить метод | Изменить проект, систему или опыт адресата |
| Основной адресат | Сам пользователь / преподаватель | Внешний пользователь, команда, сообщество |
| Примеры | Ответ на задание, личная заметка, учебный разбор | Принятый РП, опубликованный материал, применённая формализация |
| Что подтверждает | Факт учебного действия | Факт предъявленного результата |
| Чего не подтверждает | Ступень и качество освоения | Ступень 5 и реальное изменение без отдельной проверки |

Тест «может ли помочь кому-то ещё?» полезен как вопрос классификации, но не достаточен: нужен реальный адресат или приёмка.
