# [PD.METHOD.031] Node Tree + bh/cp views

## Определение

Метод удерживает три независимых представления одной системы развития:

| Представление | Вопрос |
|---|---|
| Дерево узлов | Что развивается |
| Характеристики `bh.*` | Какое поведение автоматически наблюдает Аттестатор |
| Срезы `cp.*` | Какой потенциал проверяет Диагност в конкретный момент |

Учебные ярлыки W/M1–M4 из PD.FORM.094 могут использоваться для проектирования содержания, но не являются полями текущего RCS и не подставляются вместо `bh.*`/`cp.*`.

## Назначение

Метод нужен, чтобы:

- не превращать учебную структуру программы в параллельный вычислитель ступени;
- находить развиваемый узел по наблюдениям, не смешивая событие и диагностическую оценку;
- проектировать руководство по тому, что развиваем, а не по названию поля данных.

## Inputs

| Вход | Описание | Обязателен? |
|---|---|:---:|
| Нормативная схема | PD.FORM.089 v5.0.1 с 7 `bh.*` и 13 `cp.*` | Да |
| Поведенческие события | Канонические события Activity Hub | Для автоматической части |
| Диагностический диалог | Ответы, артефакты, дата и уверенность оценки | Для `cp.*` |
| Учебная задача | Что нужно изменить в практике или проекте | Для проектирования содержания |

## Дерево узлов

```
Человек (Пилот)
├── Организм
└── Личность
    ├── Мыслительное мастерство
    └── Прикладное мастерство
        ├── Мастерство саморазвития
        ├── Мастерство управления IWE
        ├── Мастерство создания IWE
        └── Профессиональные и прочие мастерства

IWE (Машина)
├── Репозитории
├── Среда
└── Агенты
```

Программа ЛР целенаправленно работает с мыслительным мастерством, мастерством саморазвития, управления IWE и создания IWE. Личный проект остаётся внешней задачей применения и источником проверяемых следов; он не становится пятым внутренним узлом IWE.

## Два измерительных представления

### Поведение: 7 `bh.*`

`bh.sys/inv/met/awr/agn/scl/stb` рассчитывает Аттестатор из событий. Эти характеристики показывают частоту, объём, устойчивость и другие наблюдаемые аспекты поведения. Они дают рекомендуемую ступень, но не заменяют Диагноста.

### Потенциал: 13 `cp.*`

`cp.rhy/wld/skl/iwe/cre/knw/env/int/auto/exo/agt/cult/traj` оценивает Диагност по рубрикам. Для ступеней 1–4 стержневыми являются `cp.rhy/wld/skl/int`; `cp.agt` блокирует только переход 4→5; остальные срезы информационные.

**Запрет прямой проекции:** событие не создаёт `cp.*`, а ответ в диалоге не создаёт `bh.*`. Расхождение между ними снижает уверенность или требует уточнения.

## Контракт применения

| Связь | Ограничение |
|---|---|
| Живая задача → развиваемый узел | Узел называется содержательно, а не кодом показателя |
| Развиваемый узел → `bh.*` | Поведение должно быть наблюдаемым во времени |
| Развиваемый узел → `cp.*` | Качество или потенциал проверяет Диагност по рубрике |
| Узел → метод и рабочий продукт | Применение оставляет предъявимый след в живой задаче |
| Профиль → ступень | Действует только composition rule PD.FORM.089; локальная формула метода ступень не вычисляет |

## SoTA Status

**Статус:** `hypothesis`.

**Основание:** структура синхронизирована с PD.FORM.089 v5.0.1, но её удобство для совместной работы Диагноста, Навигатора и Портного ещё не подтверждено серией независимых диагностик.

**Критерий пересмотра:** после не менее пяти диагностик двумя оценщиками проверить, одинаково ли они разделяют узлы, `bh.*` и `cp.*`. Повысить статус при воспроизводимом различении; пересобрать метод, если пользователи продолжают подменять один слой другим.

## Bias-Annotation

| Bias | Direction of distortion |
|---|---|
| Код показателя подменяет объект развития | Готовый ярлык `cp.rhy` кажется содержанием рубрики, хотя это только способ диагностики |
| Видимое событие переоценивается | Коммит или число часов ошибочно трактуется как доказательство глубины и автоматически повышает `cp.*` |
| Старые учебные ярлыки принимаются за runtime-схему | W/M1–M4 удобны для разговора о содержании и поэтому незаметно возвращаются в формулы ступени |
